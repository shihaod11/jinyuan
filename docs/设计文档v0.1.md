# 暗黑刷子游戏 · 底层设计文档 v0.1

Nov 25, 2026 · @101

## 一页结论

**我的建议：做一款单机、俯视角 2D 像素风的刷子 ARPG，用 TypeScript + Phaser 4 做网页版，先只做“序章 + 第一幕”跑通全部底层系统，再往上堆内容。** 暂定名《烬渊》，可以改。

- **画面手感学《英雄围城》**：俯视角、WASD 走路、鼠标瞄准放技能、一屏几十只怪、爆装备有光柱。
- **BD 深度学《流放之路 2》**：技能来自“技能宝石”，每颗技能宝石上插 2–5 颗“辅助宝石”改变它的行为；职业只决定天赋树起点和转职方向，不锁技能。
- **底层的一句话原理**：游戏里所有数字（伤害、投射物数量、范围、攻速、抗性……）都是“属性”，装备词条、天赋点、辅助宝石、传奇特效全都只是“往属性上挂修饰器”。底层只写一套结算规则，内容全部用数据表填，所以加 100 个新词条也不用改代码。
- **规则和画面彻底分开**：伤害怎么算、掉什么装备，全在“规则层”，不依赖画面。好处是能写一个无画面的数值模拟器，一次跑一万场战斗来调平衡。
- **素材**：主用 0x72 的 16×16 地牢素材（CC0，可商用、不用署名）打底，再用同色板扩展；图标、音效用免费库；不碰暗黑、流放之路、英雄围城的任何原图和原名。

**v0.1 目标规模（第一幕可玩版）**：3 个职业起点、12 个技能宝石、20 个辅助宝石、30 种装备底材、60 条词缀、8 件传奇、约 150 个天赋节点、4 个区域 + 1 个 Boss。

**需要你拍板的 5 件事**（我都给了推荐，你不改就按推荐走）：

| # | 问题 | 我的推荐 | 备选 |
| --- | --- | --- | --- |
| 1 | 用什么引擎 | Phaser 4 网页版：免费、AI 写起来最顺、发个链接手机电脑都能打开 | Godot 4：更像“正经单机游戏”，但 AI 改场景文件更容易出错 |
| 2 | 像素精度 | 16×16（素材最多、最省事） | 32×32（更精细，免费素材少，要自己补很多） |
| 3 | 技能和职业的关系 | 流放之路式：宝石决定技能，职业决定起点 | 英雄围城式：每个职业一套固定技能树 |
| 4 | 题材 | 东方暗黑：“天渊坠火”的原创世界（见台本） | 纯西幻 |
| 5 | 联机 | 不做，只做单机 | 做联机：工作量至少翻倍，不建议第一版碰 |

## 调研结果：现在有哪些现成的

**结论：没有能直接拿来改的“开源暗黑刷子”，但素材、引擎、参考代码都够用，全部免费。** 你给的 threejs.cc 是 3D 网页作品展示站，对我们这种 2D 俯视角刷子帮助有限，适合以后做特效时参考。

## 技术选型与整体架构

**整个游戏分五层，上层可以调用下层，下层不许反过来调上层。** 最重要的一条：“规则层”不知道画面的存在，它只算数、只发事件（“哪个怪受了多少伤害”），画面层听到事件再去播特效和飘字。

从上往下调用，规则层只往上发事件（蓝色虚线）；模拟器跳过画面，直接用规则层跑战斗。

### 选型

| 部件 | 选什么 | 为什么 |
| --- | --- | --- |
| 语言 | TypeScript | 带类型检查，AI 写错字段名时编译器当场报错，比纯 JS 稳 |
| 画面引擎 | [Phaser 4](https://phaser.io/download/phaser4)（2026 年 4 月正式版，现在到 4.2.1） | 免费开源的 2D 网页引擎；新加了一次画海量精灵的功能，适合满屏怪（[更新说明](https://phaser.io/news/2026/05/phaser-3-vs-phaser-4)）；仓库自带 28 份给 AI 看的技能文件（[发布页](https://gh.hhj520.top/phaserjs/phaser/releases)） |
| 界面 | HTML/CSS 叠在游戏画面上 | 背包、提示框、天赋树全是大量文字，用网页技术做比在画布上画快很多 |
| 碰撞 | 自己写圆形碰撞 + 空间分格 | 俯视角刷子不需要物理引擎，分格查询能撑住几百只怪 |
| 地图 | 预制房间块 + 程序拼接 | 既有手设的好看，又每次不一样；房间块用免费的 Tiled 画 |
| 存档 | 浏览器本地数据库（IndexedDB） + 导出 JSON | 不要服务器，存档可以拷走备份 |
| 测试 | Vitest | 规则层纯逻辑，可以自动测伤害公式、掉落概率 |
| 打包 | 先网页；以后要上 Steam 再套桌面壳（Tauri/Electron） | 网页版改完刷新就能玩，发链接就能给朋友试 |

**为什么不用 Three.js**：它是 3D 库，做 2D 像素刷子要自己补动画、地图、镜头一整套，等于多造半个引擎。如果以后想要“2.5D”（像素人物 + 3D 光影），只需要换画面层，规则层一行不动。

**为什么不首选 Godot**：Godot 很适合做桌面单机，但它的场景文件要在编辑器里拖，AI 只能改文本、容易改坏；你要自己进编辑器的次数会多很多。网页方案里 100% 是代码和数据，AI 能全包。

### 三条硬规矩

1. **固定时间步**：规则每秒固定算 30 次，画面按显示器刷新率插值。电脑快慢不影响伤害和掉落。
2. **可复现的随机数**：所有随机（掉装备、暴击、地图）都走带种子的随机数。报 bug 时把种子发过来就能重现；以后想做联机也留了门。
3. **内容全在 data/**：加装备、加技能、加怪物只改数据表；只有“新类型的机制”才改 src/。

## 核心底层：属性、标签、触发

**刷子游戏的 BD 深度，几乎全部来自这三个小系统。** 把它们写对，后面的装备、天赋、宝石、传奇都只是“填表”。

### 1. 属性 + 修饰器（一切数字的来源）

一个“属性”就是一个名字，比如“火焰伤害”“投射物数量”“最大生命”。一个“修饰器”就是挂在属性上的一句话，来自装备词条、天赋点、辅助宝石、增益状态。修饰器只有 5 种：

| 类型 | 游戏里的写法 | 怎么叠加 |
| --- | --- | --- |
| 固定值 | +25 最大生命 | 先全部相加 |
| 提高 | 火焰伤害提高 30% | 所有“提高”先加在一起，再乘一次 |
| 更多 | 伤害 25% 更多 | 每一条单独相乘（所以更值钱） |
| 覆盖 | 你的爆击率固定为 100% | 直接替换结果，传奇和基石天赋专用 |
| 开关 | 你的技能消耗生命而不是法力 | 打开一个规则，由对应系统自己去读 |

```latex
\text{最终值} = (\text{基础} + \sum \text{固定}) \times (1 + \sum \text{提高}\%) \times \prod (1 + \text{更多}\%)
```

“提高”和“更多”分开，是整个数值体系的关键：堆 10 条“提高 20%”只是 ×3，而 4 个“更多 25%”是 ×2.44。玩家慢慢学会“缺什么就补什么”，这就是 BD 的乐趣。

### 2. 标签（决定哪条修饰器对哪个技能生效）

每个技能身上贴着一组标签，比如“火球”= 法术、投射物、火焰、范围。修饰器也带标签条件：“投射物伤害提高 20%”只对带“投射物”标签的技能生效。

- 第一版标签：攻击、法术、近战、投射物、范围、持续、引导、召唤物、图腾、陷阱、光环、增益、移动、触发、重击、物理、火、冰、电、混沌，共 20 个。
- 标签在内存里存成一串二进制位，判断“这条修饰器对这个技能生不生效”只要一次位运算，满屏技能也不卡。
- 转化会继承标签：物理伤害转成火焰后，“物理伤害提高”和“火焰伤害提高”都算，这是很多 BD 的核心玩法。

### 3. 事件触发（传奇、元宝石、天赋的“特效”都靠它）

规则层在关键时刻发出事件，任何东西都可以“监听”事件并做一件事。一条触发 = 什么时候 + 什么条件 + 几率 + 冷却 + 做什么。

| 部分 | 第一版可选项 |
| --- | --- |
| 什么时候 | 命中时、暴击时、击杀时、被击中时、格挡时、使用技能时、翻滚后、施加异常时、召唤物死亡时、每 N 秒 |
| 什么条件 | 敌人已点燃/感电/冻结、自己低血、满能量护盾、近期移动过、敌人是稀有/Boss |
| 做什么 | 释放某技能、加一层增益、生成实体（爆炸、地面、召唤物）、恢复资源、把异常扩散给周围 |

例：传奇剑“击杀被点燃的敌人时，点燃扩散到 3 米内的敌人” = 击杀时 + 敌人已点燃 + 100% + 无冷却 + 扩散点燃。没有一行专门代码，全是拼出来的。这样做传奇的速度只取决于你的点子，不取决于代码量。

**怪物也走同一套系统**：怪物的攻击就是技能宝石，精英怪的“火焰附魔”“迅捷”就是修饰器。一套代码两边用，玩家能用的机制怪物也能用。

## 技能系统：宝石 = 积木

**一个技能由“怎么放出去”和“打到以后发生什么”两块积木拼成；辅助宝石不写代码，只是一包修饰器。** 比如“多重投射”辅助就是两条修饰器：投射物数量 +2、伤害 30% 更少。因为“投射物数量”本身就是属性，火球、冰矛、弓箭自动都能用。

### 四种宝石

| 宝石 | 作用 | 规则 |
| --- | --- | --- |
| 技能宝石 | 给你一个主动技能 | 最多装 8 颗，绑定鼠标左右键 + 1–6 键；等级 1–20 |
| 辅助宝石 | 插在技能宝石上，改变它 | 每颗技能宝石自带 2 个孔，用通货最多扩到 5 个；同一种辅助全身只能用 1 次，逼你取舍 |
| 精魂宝石 | 光环、护甲、常驻召唤物这类“一直开着”的效果 | 占用“精魂”：初始 30，剧情奖励 +30 × 2，项链和胸甲可以再加 |
| 元宝石 | 宝石里套宝石：“暴击时自动施放里面的法术” | 也占精魂，内部用的是上一节的事件触发 |

宝石的来历写进了世界观：怪物被杀后凝出“烬晶”，就是宝石（见台本）。掉落的是“未切割的烬晶”，实例化时玩家自己选技能，避免“一直刷不到想要的技能”。

### 积木一：怎么放出去（投放方式）

| 投放方式 | 关键属性（都能被辅助改） |
| --- | --- |
| 投射物 | 数量、速度、散射角、穿透、连锁、分叉、返回、存在时间 |
| 范围 | 半径、延迟、形状（圆/扇/矩形）、重复次数 |
| 近战打击 | 角度、距离、每次命中数 |
| 引导/光束 | 每秒跳数、长度、宽度 |
| 地面 | 持续时间、每秒跳数、半径 |
| 召唤 | 数量上限、召唤物属性、召唤物自己的技能 |
| 图腾/陷阱 | 数量上限、放置速度、触发半径 |
| 位移 | 距离、无敌时间、落地效果 |

组合可以套娃：“火球命中后爆炸成范围”“图腾释放投射物”“召唤物的攻击触发你的点燃”都是积木接积木。

### 积木二：打到以后（载荷）

伤害（各类型的最小–最大值，或“武器伤害的 X%”）、异常状态（点燃、感电、冻结、流血、中毒）、击退、加减益，以及“命中时触发”的后续积木。

## 装备系统

**一件装备 = 底材 + 物品等级 + 稀有度 + 词缀 + 孔 + 镶嵌物。** 所有词缀最后都变成修饰器，交给属性系统。

### 底材（白板装备）

- **部位 11 个**：主手、副手、头、胸、手、脚、腰带、项链、戒指×2、护符。
- **武器类型 8 种**：剑、斧、锤、匕首、弓、法杖、长杖、弩。每种有自己的基础伤害、攻速、暴击率，还自带一条“固有词缀”（比如匕首天生 +暴击）。
- **防具三条路**：护甲（力量）、闪避（敏捷）、能量护盾（智力），以及两两混合。
- **同一部位分档**：每类底材有 4–5 档，需求等级 1 / 15 / 30 / 50 / 70。高档底材基础值更高，带动后期换装。

### 稀有度

| 稀有度 | 颜色 | 词缀 | 用途 |
| --- | --- | --- | --- |
| 普通 | 白 | 0 | 做符文之语的底子、用通货改造 |
| 魔法 | 蓝 | 1–2（前缀、后缀各最多 1） | 前期过渡；单条高档词缀有价值 |
| 稀有 | 黄 | 3–6（前缀、后缀各最多 3） | 主力装备，刷子的主体 |
| 传奇 | 橙 | 固定词缀 + 1–2 条特效 | 改变玩法，核心 BD 来源 |

前缀管“打得疼、血厚”（伤害、生命、护甲、移速），后缀管“打得快、抗得住”（攻速、暴击、抗性、属性、回复）。同一个词缀组不重复出现。

### 词缀怎么生成

1. 物品等级 = 掉落它的怪物等级。物品等级决定能出哪些档位。
2. 从“这个部位可以出、还没出过、档位够得上”的词缀里，按权重抽一个。
3. 在该档位的数值范围内再随机一个数。
4. 高档位权重低：最高两档权重分别是普通档的 50% 和 25%，所以“满档黄装”很稀罕，刷的动力就在这。

### 孔与镶嵌物

**装备上的孔和技能宝石无关，只用来插“镶嵌物”。** 这样两套系统不打架，换装备不会把技能搭配拆掉。

| 镶嵌物 | 来源 | 效果 |
| --- | --- | --- |
| 符文 | 普通掉落，分 1–15 级 | 固定效果，而且插在武器和防具上效果不同（如“炎符”：武器上加火伤，防具上加火抗） |
| 珠宝 | 稀有掉落，有随机小词缀 | 可以插装备，也可以插在天赋树的“珠宝槽”里 |
| 魂核 | Boss 专属掉落 | 带触发特效（如“低血时获得 3 秒护盾”） |

- 孔数：单手武器/头/手/脚 0–2，双手武器/胸甲 0–3，首饰 0–1。用“凿孔石”加孔。
- **符文之语**（第二幕后解锁）：在孔数刚好的白色底材里，按顺序插入特定符文，装备变成有名字的强力装备。白板装备因此也值得捡。

## 伤害结算与防御公式

**一次命中按固定的 9 步算完，顺序永远不变。** 顺序固定，提示框里的 DPS 才能和实战一致，玩家才能“算”BD。

### 进攻方：伤害怎么来

1. **基础伤害**：攻击技能取武器伤害 × 技能倍率；法术取宝石等级对应的基础值。
2. **附加固定伤害**：“附加 5–12 火焰伤害”这类词缀加上去。
3. **转化**：顺序固定为 物理 → 电 → 冰 → 火 → 混沌，只能往后转，总量最多 100%。
4. **额外获得**：“获得物理伤害的 20% 作为额外火焰伤害”。
5. **放大**：按属性公式算“提高”和“更多”，转化来的伤害同时吃原类型和新类型的加成。
6. **命中判定**（只有攻击）：精准 vs 闪避。法术必中。
7. **暴击**：暴击率上限 100%；基础暴击伤害加成 +100%（即×2）。
8. **对方减免**：见下一小节。
9. **异常与后续**：算完最终伤害后，判定点燃/感电/冻结/流血/中毒，算生命偷取，发出“命中”“暴击”“击杀”事件。

### 防守方：伤害怎么减

命中率（上下限 5%–100%）：

```latex
\text{命中率} = \frac{1.25 \times \text{精准}}{\text{精准} + (0.2 \times \text{闪避})^{0.9}}
```

闪避不纯靠运气：每个敌人对你有一个“命中计数器”，命中率 60% 就严格每 10 下中 6 下左右，不会连续闪或连续被打中。

护甲减物理伤害（上限 90%），打得越重，护甲越不管用：

```latex
\text{物理减伤} = \frac{\text{护甲}}{\text{护甲} + 5 \times \text{这一下的伤害}}
```

| 防御手段 | 规则 |
| --- | --- |
| 元素抗性 | 火/冰/电各自算，上限 75%（装备和天赋可以提到 90%）；第二幕后 −20%，第四幕后 −40%，逼玩家挂抗性词缀 |
| 混沌抗性 | 不受剧情惩罚，但只有少数词缀能提供 |
| 穿透 | 进攻方的“穿透 15% 火抗”只在这一下抵消对方抗性 |
| 格挡 | 盾牌提供，上限 75%，格挡成功伤害归零 |
| 能量护盾 | 先扣护盾再扣生命；2 秒不受伤后开始快速回复 |
| 翻滚 | 空格键，0.35 秒内前 0.15 秒无敌，冷却 1 秒；英雄围城没有这个，但它让 Boss 战更有技巧 |

### 五种异常（第一版数值）

| 异常 | 来自 | 效果 |
| --- | --- | --- |
| 点燃 | 火焰命中，按几率 | 4 秒内共造成这一下火伤的 80%；同时只生效最强的一个 |

## 数值框架（初稿，等模拟器跑完再调）

### 成长公式（L = 等级，怪物等级最高 85）

```latex
\text{普通怪生命}(L) = 18 \times 1.08^{L-1} \times (1 + 0.05(L-1))
```

```latex
\text{普通怪单次伤害}(L) = 6 \times 1.05^{L-1} \times (1 + 0.025(L-1))
```

```latex
\text{升级所需经验}(L) = (40L^{2.6} + 120L) \times (1 + 0.12\max(0, L-60)) \times (1 + 0.25\max(0, L-85))
```

## 台本：《烬渊》

**一句话故事：天裂了，黑火落下，杀怪能捡到力量；你一路杀到天上，发现最想把天撑大的恰恰是保护人间的教会。** 每一幕解锁一个系统，剧情就是教程。

### 世界观

- **天渊**：三百年前天穹裂开一道缝，落下黑色的“渊火”。被渊火烧过的死者会站起来，活物会变异。
- **烬晶**：渊火怪物死后会凝出晶体，人吸收它就能使出对应的力量。这就是宝石。
- **拾烬人**：靠杀怪、卖烬晶过日子的人。普通人最多驾驭一两颗烬晶，多了会疯。
- **主角**：一个拾烬人，在边境灰石村醒来，胸口有一块取不出来的“渊心碎片”。它让你能同时驾驭很多颗烬晶，这解释了玩家为什么能装 8 个技能。
- **圣火庭**：对抗渊火的教会，宣称在守护人间。实际上大主祭在用烬晶喂养天渊，换自己的永生。

## 开发路线图、风险与真话

**先做“核心规则 + 一幕内容”，业余时间大约 15–18 周（约 4 个月）能拿出可以给朋友试玩的 v0.1。** 每个里程碑都有验收标准，没过就不往下走。时间是我按“你每周抽几个晚上 + AI 写代码”估的，可能偏差很大。

### 风险与真话

- **最难的不是代码，是内容量和平衡。** 流放之路 2 的 440 个宝石是一家专业公司做了多年的。我们的对策是“积木 + 填表 + 模拟器”，把内容成本压到最低，但你仍要花大量时间想传奇和调数值。
- **美术统一是最大的视觉风险。** 免费素材混着用会像拼盘。定一套主素材（0x72）和一张色板，其他素材和 AI 生成的图都先重新上色再用。
- **版权红线。** 机制可以借鉴；名字、图标、美术、文案、具体数据表不能搬。CC-BY-SA 和 GPL 的东西不混进来。我不是律师，如果以后要上 Steam 收费，上架前请专业的人看一眼。
- **手机版**：网页在手机上能打开，但刷子要虚拟摇杆和技能按钮，第一版只保证电脑键鼠。
- **联机**：第一版不做。固定时间步 + 可复现随机数已经给以后留了门。
- **先做好的小事**：每个里程碑结束都更新 docs/交接.md，换新对话也能接着干。
